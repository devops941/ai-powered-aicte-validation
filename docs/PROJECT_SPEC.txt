AICTE VeriSense: AI-Powered Application Validation, Document Authentication and Regulatory Compliance Verification 

Problem
AICTE's verification of Extension of Approval (EoA) applications is largely manual. Officials must scrutinise a large volume of documents, including NOCs, affidavits, faculty records and infrastructure details. Submissions often contain missing, expired, altered or inconsistent files, and confirmations from issuing authorities are delayed. This makes processing slow, error-prone and hard to keep consistent, and it leaves officials spending time on routine checks instead of the cases that need judgement.

Proposed Solution
AICTE VeriSense is an AI-enabled decision-support system that pre-validates applications before they reach an official. It does not replace AICTE's existing systems or its decision-making. It works as an additive layer connected through standard REST APIs.

When an application is received, the system detects its category and automatically loads the matching checklist from the Approval Process Handbook. It then runs five parallel checks:

Document OCR, data extraction and completeness check (PaddleOCR / DocTR with LayoutLMv3 / Donut).
Cross-check against the institution's historical records in AICTE systems.
Anomaly and potential forgery detection using OpenCV and PyTorch (CNN-Transformer hybrids).
Issuing-authority verification where possible, through APIs, QR codes and digital signatures.
Infrastructure evidence analysis using computer vision (YOLOv8 / Detectron2) to flag cases that may need physical inspection.

The results are combined into a structured Validation Report with a risk score and links to the evidence. Cases needing attention are shown on a dashboard for authorized officials only, and every step is recorded in an immutable audit trail.

Key Innovations

Evidence-linked, explainable flags. Each flag shows the exact evidence, the rule applied, the source and a timestamp, so there are no black-box decisions.
Hybrid pipeline. AICTE records, OCR, anomaly detection and issuing-authority verification work together in one workflow.
No-code rules engine. JSON/YAML rules and decision trees keep the system aligned with the latest Handbook without code changes.
Cross-document consistency checks that catch mismatches across submitted files.
Human-in-the-loop by design. The AI never auto-approves or auto-rejects, and infrastructure vision checks are advisory only. Final authority stays with AICTE officials.
Graceful fallback. If an external source is unavailable, the case is marked "Manual Review Required".

Technical Approach

Frontend: React, Tailwind, Recharts
Backend: FastAPI
Document AI: PaddleOCR / DocTR, LayoutLMv3 / Donut
Forgery detection: OpenCV, PyTorch
Infrastructure CV: YOLOv8 / Detectron2
Rules engine: JSON/YAML rules and decision trees
Storage: PostgreSQL, MinIO
Security: JWT-based RBAC, encryption at rest, access logging
Integration: REST APIs for the AICTE portal and external sources

Prototype Status
About 50% of the prototype is complete. The core modules are in place, including the executive scrutiny dashboard, application intake and queue, document viewer and OCR, validation modules, risk and evidence explorer, validation report, institutional history, and checklist and rules management. The remaining features and improvements are in progress. The prototype is being demonstrated on synthetic and anonymized datasets covering clean, incomplete, expired, anomalous and infrastructure-gap cases.

Feasibility and Viability
The solution is built on mature open-source OCR, computer vision and anomaly-detection tools. The core modules (OCR, consistency checks, anomaly flags and dashboard) can be built within hackathon timelines. The main challenges and mitigations are:

Limited real data: synthetic and anonymized datasets.
Evolving Handbook: configurable rules engine.
Unavailable external sources: manual-review fallback.
False positives: evidence-linked flags with mandatory human verification.
Data security: role-based access, encryption, audit logs and a retention policy.

The path to production is: prototype, then a limited-category pilot, then full AICTE integration. It can be deployed as a secure government-cloud service with role-based access.

Impact and Benefits

Cuts repetitive manual scrutiny and reduces processing time.
Detects missing, expired, inconsistent or anomalous submissions early.
Improves consistency, transparency, auditability and accountability.
Lets officials focus only on flagged cases that need human attention or inspection.
Identifies infrastructure and compliance gaps early.
Extends to UGC and State Technical Boards, giving a reusable compliance engine that improves with more data and updated rules.

Outcome
AICTE VeriSense gives faster, fairer and fully auditable approvals. Automation handles routine pre-validation, and final decisions stay with AICTE officials.
